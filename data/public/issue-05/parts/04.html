diagram-design

GitHub 上的开源项目。它是一个给 AI 编程工具用的绘图 skill：你用平常说话的方式描述要画的图，AI 选出合适的类型，写出一个可双击打开的 HTML 文件，图以 SVG 内嵌其中。共 52 种图。风格克制：细线、少阴影、突出一两处重点。也可以从 Mermaid、draw.io、Excalidraw、PlantUML 导入后重画。

它能做什么

  • 一条命令安装：npx skills add cathrynlavery/diagram-design。Claude Code、Codex、Cursor、GitHub Copilot 等也有对应的插件装法。
  • 能画架构图、流程图、时序图、状态图、数据模型等；也可按你的网站提取颜色和字体，让后续的图跟品牌一致。
  • 成品是单个 HTML 文件，可再导出为 PNG 或 SVG。仓库提供 self_check.py 检查重叠和裁切。
  • 作者自己也写明：要跟代码一起频繁改动的图，仍更适合 Mermaid。

最突出的点

对 AI 说一句人话，得到一张能拿去发布的图

默认的 AI 绘图常常是圆角方块加阴影。这个 skill 把「口味」写进了规则：一种强调色、细线、坐标对齐到 4 的倍数，阅读时先看到那一两处重点。

适合谁用

要为文章、说明文档或产品介绍配图的人。不会写代码也可以：装上 skill，用一句话说出你想画什么。

缺点与应对

  1. 缺点1：效果取决于你用的模型。同一句提示，两次布局可能不一样。 应对：先让 AI 说出要用哪一种图、突出哪一两处，再画；用自带检查脚本看重叠；不满意就指定类型再画一次。
  2. 缺点2：产出不是方便在 Git 里逐行对比的源码。改来改去会比较费事。 应对：要经常随代码更新的图，用 Mermaid；要拿去发布、做封面或文章配图，用这个。
  3. 缺点3：默认可能加载 Google Fonts，打开时会联网。 应对：改用系统字体；需要离线检查时，按文档给检查脚本加上相应参数。
技术含金量

它把设计规则写成 AI 能执行的约束：一种强调色、细线、网格对齐，并且先声明计划再落笔。产出是自包含的 HTML 和 SVG，发布时少依赖外部服务。作者还写了一条很好用的判断：如果一段写清楚的文字已经够了，就不要为了「有图」再画一张。

技术关联

① 热门技术取舍：第一、二期的 impeccable、hallmark 管的是页面和界面不要「AI 味」。diagram-design 专管图表。第四期的 stitch-skills 偏向出设计稿。需要一张能放进文章的结构图或流程图，用这一个；要改界面审美，去用前面那些。
