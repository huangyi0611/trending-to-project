stitch-skills

GitHub 上的开源项目，Google Labs 给自家 AI 设计工具 Stitch 做的一套 skill。装进 Claude Code、Codex、Cursor 等工具后，AI 能帮你在 Stitch 里生成界面设计稿、改稿、出几个版本，再把设计稿转成 React 或 React Native 代码；也能反过来，从你现有的网页代码里整理出一份设计规范（DESIGN.md）传到 Stitch。

它能做什么

  • 设计：用文字或图片生成新界面、改已有界面、出几个版本；把设计规范 DESIGN.md 套到所有页面上。
  • 设计变代码：把 Stitch 设计稿转成 React 组件、React Native 组件或 React + Vite 后台页面，并检查颜色、字号这些设计变量前后一致。
  • 代码变设计：从现有前端代码里提取 DESIGN.md，或把正在运行的网页存成单个 HTML 再传到 Stitch。
  • 小工具：enhance-prompt 把模糊的界面想法改写成专业的设计提示词；还能用 Remotion 把设计稿做成演示视频。

最突出的点

设计规范写成一个 DESIGN.md，人和 AI 共用

它把设计系统落成一个纯文本文件 DESIGN.md：颜色、字体、间距、组件风格都写在里面。AI 生成新页面时照着它来，换个工具也能接着用。没有设计师的独立开发者，靠它统一界面风格最省事。

适合谁用

没有设计师、想快速出界面草稿的独立开发者；想先看到「长什么样」再决定做不做的非程序员。

缺点与应对

  1. 缺点1：离不开 Google Stitch。所有 skill 都要先配好 Stitch MCP 服务，设计稿存在 Google 的服务上。 应对：先在 Stitch 网页版试几次，觉得好用再装 skill。不想依赖云服务，就只学它的 DESIGN.md 写法。
  2. 缺点2：转代码只有 React 一系。设计稿转代码只有 React、React Native、React + Vite 几条路，没有手机原生界面框架的输出。 应对：原生 App 只把设计稿当参考图，再让 AI 照着截图用你自己的界面框架实现。
  3. 缺点3：仓库更新放缓，单独挑着装容易缺东西。抓取时最近一次推送是 2026-08-18（北京时间），最新版 v1.0 发布于 2026 年 5 月；skill 之间有依赖。 应对：按 README 推荐的插件方式整套装；遇到问题先翻 issue（未解决约 12 个）。
技术含金量

价值在于把设计变成 AI 能读、能改、能传递的文本。DESIGN.md 相当于设计系统的「源代码」：放在仓库里，能看历史、能比差异。设计和代码双向转换，也是大厂设计团队在追的方向。

它按 Agent Skills 开放标准写，每个 skill 只管一件事（出图、提取规范、转代码、做视频），彼此靠 DESIGN.md 串起来，是「小模块 + 统一接口」的好例子。

技术关联

① 热门技术取舍：只想让 AI 做的页面少点「AI 味」：第二期的 hallmark 或第一期的 impeccable 更直接，也不依赖云服务。想要看得见的设计稿、几个版本对比着挑：用 Stitch 加这套 skill。已经有成熟组件库：第三期 astryx 那类设计系统更合适。三条路选一条做主线，DESIGN.md 的写法哪条都能借鉴。

上榜原因 · 许可证与维护风险
