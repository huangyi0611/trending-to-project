SkillEvaluator

GitHub 上的开源项目，NVIDIA 开源的 skill 评测工具。skill 是交给 AI 的一份任务说明书（一个文件夹，里面有 SKILL.md 和配套文件）。它先查这份说明书写得规不规范、安不安全，再找出重复、互相打架的内容，最后让 AI 带着 skill 和不带 skill 各做一遍任务，看这份 skill 到底有没有用。

它能做什么

  • 第一层「校验」：查格式、安全和兼容性，不需要 API key。官方示例 skill 得 86.2 分（B），默认 70 分及格。
  • 第二层「去重」：找出说明里重复或重叠的内容；还能拿你的几个 skill 互相比，看有没有抢活的。
  • 第三层「实测」：在沙盒里让 AI 带 / 不带这个 skill 做同样的任务，比较结果。需要模型服务、受支持的 AI 工具和 Docker。
  • 接进 GitHub：skillevaluator ci init 自动开一个 PR，以后每次改 skill 都自动检查；也能当 skill 装进 Claude Code、Codex，直接问「我的 skill 好不好」。

最突出的点

给 skill 做体检，再做对照实验

大家都在写 skill，很少有人测过它到底让 AI 变好了没有。SkillEvaluator 拆成三层：前两层几分钟出结果，第一层连密钥都不用；第三层用对照实验看真实效果。写 skill 的人终于有了能量化的分数。

适合谁用

自己写 skill、或者装了很多别人 skill 的人。非程序员也能用第一层：把 skill 文件夹交给它，看报告里哪里扣分。

缺点与应对

  1. 缺点1：第三层门槛高，可能花钱。要模型服务和沙盒（默认 Docker），README 提醒模型和托管沙盒会产生费用。 应对：先只跑第一层（加 --tiers 1），确实需要再开第三层，开之前看官方的成本说明。
  2. 缺点2：分数只是参考。第一层查的是写法，及格不等于好用；第三层自动生成的测试用例覆盖有限，README 也提醒要人工复核。 应对：给自己的 skill 写几条真实任务和期望结果，放进 evals/EVAL.md，让实测贴近你的用法。
  3. 缺点3：第一层会自动下载安全扫描工具，对 Python 版本有要求。缺 SkillSpector、Gitleaks 时会自动下载固定版本；需要 Python 3.12 以上。 应对：用 uv 运行，它会自动准备 Python；公司电脑先确认能不能下载这些工具。
技术含金量

价值在于把「写说明书」变成能测的工程。三层逐级加码：便宜的静态检查挡住大部分问题，贵的实测只留给通过前两层的 skill，这是工程里常见的漏斗式质检。

第二层很有远见：skill 装多了，说明之间会重复、打架，AI 反而不知道听谁的。用相似度检测提前发现，和代码里「消除重复」是一个道理。它是 NVIDIA「Verified Skills」流程的一部分，还配了论文。

技术关联

① 热门技术取舍：只写一两个 skill：第一层体检就够。skill 多了、开始互相干扰：加第二层。skill 要给很多人用，或者你想证明它真有效：上第三层。本期 modern-web-guidance 用的也是「装与不装」对照的思路，可以一起看。
