modern-web-guidance-src

GitHub 上的开源项目，Google Chrome 团队牵头，Microsoft Edge、Mozilla Firefox 和 MDN 团队一起维护。它是一套给 AI 编程工具用的网页知识包：AI 写网页时，先按需查一篇最新的官方写法指南，少写过时、臃肿的代码。这个仓库是源码库，放指南的编写、校准和评测工具；用户实际安装的是 GoogleChrome/modern-web-guidance。

它能做什么

  • 一条命令装进 AI 工具：npx modern-web-guidance@latest install 会打开安装向导；也支持 npx skills add、gh skill install 和 Claude Code、Codex 的插件市场。
  • AI 写网页时按需查指南，覆盖约 250 个现代网页功能：弹窗、悬浮提示、页面切换动画、深色模式、表单校验、图片加载提速、无障碍（读屏和键盘操作）等。
  • 不装也能试：search 搜指南，retrieve 取一篇全文，legacy-scan . 扫一遍你的代码，找出能换成新写法的老代码。
  • 另有一个 Chrome 扩展开发的知识包，讲 Manifest V3、后台脚本和上架 Chrome Web Store。

最突出的点

有对照实验：装上以后，AI 写网页的通过率涨了约 30 个百分点

它每隔两天用真实网页任务测一次：同一个 AI，不装指南和装了指南各做一遍，用自动化检查打分。README 公布的 11 月 8 日结果：Claude Code 从 57% 提到 88%，Codex 从 54% 提到 82%，Antigravity 从 58% 提到 94%。拿做对率说话，很实在。

适合谁用

让 AI 写网页、落地页、小工具页面的人。非程序员做个人主页、活动页也用得上：AI 少用笨重的老办法，页面更快，手机上也更顺。

缺点与应对

  1. 缺点1：只管网页。它讲的是浏览器里的 HTML、CSS、JavaScript，对手机原生 App 和后端接口帮不上忙。 应对：只在网页项目里装。原生 App 的界面规范，看平台官方文档。
  2. 缺点2：默认收集匿名使用数据。README 写明会收集安装次数、调用它的 AI 工具名、查了哪些指南、AI 生成的搜索词；不收集你的原始提示词。 应对：在 shell 配置文件里加 DISABLE_TELEMETRY=1 关掉。
  3. 缺点3：新写法要看浏览器支持。它覆盖到最前沿的功能，有些功能旧浏览器还不认。 应对：让 AI 每用一个新功能都说明哪些浏览器支持、不支持时怎么降级（README 也强调用轻量的降级办法）；上线前用手机 Safari 和一个旧版浏览器各看一次。
技术含金量

价值在于对付 AI 的「知识过期」：模型训练数据里老代码多，它就习惯写老办法。这个项目把指南压得很短（装进 AI 的入口说明约 205 个 token），用到时才查全文，不多占 AI 的上下文。

更值得学的是评测方法：每个任务先准备标准答案（打分器必须给 100% 通过）和没改过的原始网页（必须 100% 不通过），用来校准打分器；再比较 AI 装与不装指南的通过率。模型本来就会的内容删掉，只留真正能提分的。这套「先出考卷再写教材」的做法，任何写 skill 的人都能照搬。

技术关联

① 热门技术取舍：只想让 AI 做的页面更好看：第一、二期的 impeccable、hallmark 管审美。想让页面用对浏览器新功能、跑得快、读屏能用：用这一个。审美和写法是两件事，可以同时装；每多装一个 skill，AI 要读的说明就多一份，先挑你最缺的那个。
