Plannotator

GitHub 上的开源项目。AI 写代码前会先出一份计划（plan），Plannotator 把这份计划在浏览器里打开，你像批改作文一样划线、写批注，点一下就把意见发回给 AI；AI 改完，还会标出计划前后的差别。代码写完，它也能打开审查页面，让你逐行点评本地改动或 GitHub 上的 PR。支持 Claude Code、Codex、Gemini CLI、Copilot CLI、OpenCode 等十来种 AI 编程工具。

它能做什么

  • 审计划：AI 准备动手时，计划自动在浏览器里弹出。你逐段批注，点「通过」AI 才往下做；点「打回」，批注会整理好发回去，AI 改完再给你看前后差别。
  • 审代码：/plannotator-review 打开本地还没提交的改动，或一个 GitHub / GitLab 的 PR，逐行写意见，意见直接回到 AI 的对话里。
  • 批注任何文档：/plannotator-annotate 能打开 Markdown 文件、整个文件夹、网址或 HTML 页面；/plannotator-last 批注 AI 刚才那条回复。
  • Inbox（收件箱）：几个 AI 同时干活时，把问题、文件、待审内容都投到一个本地窗口，你有空再统一回复，AI 不用干等。批准过的计划还能自动存进 Obsidian、Notion 或 Bear。

最突出的点

给 AI 的计划配一支红笔

AI 最贵的错，是一开始方向就错，写了几百行才发现。Plannotator 把「审计划」做得像改作文一样顺手：划一句，写一句意见，点发送。人只在两个关口出手：动手前看计划，合并前看改动。

适合谁用

已经在用 Claude Code、Codex 这类工具写代码，常遇到「AI 理解错需求、一口气改了一大片」的人。不会写代码也能用：看得懂计划、会写中文批注就行。

缺点与应对

  1. 缺点1：计划自动弹出，要靠各家 AI 工具的钩子（hooks）。Codex 用的是还在实验的 Stop 钩子，原生 Windows 要手动配置；Droid 目前只支持手动命令。 应对：先用最稳的 /plannotator-last 和 /plannotator-review 两个手动命令，熟了再开自动审计划。装完先在一个练手仓库里试一次。
  2. 缺点2：有几个功能会联网。页面打开时会向 GitHub 查新版本；批注网址默认经 Jina Reader 抓取；「问 AI」会把相关内容发给你配置的模型；分享链接时内容跟着链接走，小份内容只压缩、没加密。 应对：私密代码别用分享链接，可以设置 PLANNOTATOR_SHARE=disabled 把分享关掉。远程模式会在所有网卡上开端口、不用登录，只在可信网络里用。
  3. 缺点3：安装是「一行命令下载脚本直接运行」，还会改你 AI 工具的配置。 应对：先打开安装脚本看一眼，或加 --minimal 只装主程序；想撤销就运行 plannotator uninstall，默认保留你的计划和历史。
技术含金量

价值在于把「人在回路」（Human-in-the-loop，关键一步由人拍板）放在最便宜的位置。计划只有几十行，改计划几分钟；等代码写完再返工，代价大得多。它挂在 AI 工具自带的钩子上（AI 准备结束计划模式时触发），你的工作习惯不用变。

设计也克制：数据默认留在本机，不收集使用数据；意见按结构化格式发回 AI，AI 改完显示计划前后差别，人一眼看出改了哪里。能批注的对象从代码扩大到计划、文档和 HTML 页面，AI 产出的东西都能过一遍人眼。

技术关联

① 热门技术取舍：只想审代码：第三期的 pr-agent，或本期的 open-code-review，让 AI 先审一遍就够。想把计划、文档、代码都过一遍人眼：用 Plannotator。团队要固定流程、多个角色、审批节点：看本期的 LoopForge。三者可以叠加：Plannotator 管人怎么批，open-code-review 管 AI 先挑错，LoopForge 管整条流程怎么排。个人开发者先装 Plannotator 一个就够。
