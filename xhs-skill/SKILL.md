# GitHub 热榜拆解 · 公开快照 Skill

作者：假笑黄黄AI版。本文件是 Skill 源码包的入口。它和小红书「小工具容器」那个只含 HTML/CSS/JS 的 ZIP 不是同一种上传格式，也不能当成那份容器已经通过审核。

本包自己不联网、不追踪、不把对话写进存储。回答必须来自包内静态文件，不能靠打开网页就算完成。

## 依赖

没有运行时依赖，不必安装语言包或第三方库。

- 要回答问题，读 `data/issues.json` 和 `data/glossary.json`。字段说明在 `data/README.txt`。
- `reader/index.html`、`reader/app.css`、`reader/app.js`、`reader/data.js` 是同一份快照的可选展示页，页面脚本不发网络请求。平台能不能打开 HTML，由平台决定。打不开时仍然用 JSON 回答，不要改口说「只能打开 index」。
- 许可原文在 `LICENSE.txt`（与无扩展名的 `LICENSE` 文字相同）、`LICENSE-CONTENT.md`、`NOTICE.md`。代码按 PolyForm Noncommercial 1.0.0，正文和释义按 CC BY-NC-SA 4.0。不要改写这两份许可。`LICENSE-CONTENT.md` 会点到仓库里其他说明文件的名字，那些目录不在本 ZIP 里，不要按那个清单去包外找。

不要到本包外面找仓库目录、私人文件或别的期次。包里没有的内容就说没有。

## 何时使用

使用本 Skill：

- 用户问第03期、第04期、热榜拆解、某一期最推荐、某个项目能不能学
- 用户给一个关键词，或一个学习目标（写需求、写代码、界面、审查、发布等）
- 用户点名一个术语，要白话解释
- 用户明确写下自己的项目，并要求对照本期

不要使用本 Skill 去查「今天的实时热榜」、刷新星数、承诺平台会自动推送下一期，或在用户没要求时运行 HTML。

## 回答步骤

1. 读 `data/issues.json`。`issuesAvailable` 只有 `03` 和 `04`。用户要别的期，直接说明本包没有正文。
2. 选期。用户指定期号就用那一期；没指定时先问，或者同时给出两期的 `summary` 让用户选。不要默认把两期揉成一个新榜。
3. 按关键词筛选时，在该期每张卡的 `searchText`、`name`、`repo`、`tags` 里找，保留命中的卡，并说明命中了哪一类信息。一个词出现在别的卡的取舍段里时，可以同时留下那张卡，但要说清是「文中提到」还是「这张卡本身」。
4. 按学习目标筛选时，先对上 `stages`：想法 `idea`，写需求 `spec`，写代码 `code`，记忆和上下文 `memory`，数据和知识 `data`，界面 `ui`，测试、审查和安全 `qa`，发布和内容 `ship`。用 `cards[].stageKey` 取出这一步的项目。对不上阶段名时，再退回关键词检索，不要硬塞。
5. 拆解一张卡时用白话，句子短。英文术语第一次出现时用括号补中文，并尽量用 `data/glossary.json` 的 `what` 和 `like`。先查 `entries` 的键，没有再查 `aliases`。词库没有的词就说「这份预置释义里没有」，不要编一条。
6. 每条项目回答都要带上：期号、`sampling.when` 或 `sampling.statement`、`repo` 文字名、`starSnapshot`（没有就说明这张卡的快照里没有单独星数）。明确说这是采样，不是现在的星数。
7. 风险至少写一条，优先用 `drawbacks`，并带上对应的 `response`。许可证与维护风险在 `sections` 里标题含「上榜原因」的那段，不要省略。上手难度是 `difficulty.stars`，满分 5，是估计，不是 GitHub 星数。
8. 最推荐只认 `featured` 为 true 的那一张，不要另选。

## 项目适配

默认不做。只有用户在当前对话里主动写出项目做什么、给谁用，并明确要求对照时才做。技术栈和目标可以缺，缺了就问，不要猜。

对照时仍然只用本包里的公开卡片。用户没提到的仓库不要安到他的项目上。不要向包外读取任何项目文件。不要让用户把密钥、密码、令牌、验证码或绝对路径发过来；如果已经发了，提醒删掉，并且不要在回答里复述。

本包不收集、不上传这些内容。用户如果把项目信息发给平台上的 AI，那些信息按该平台自己的数据政策处理。不要说平台 AI 端百分之百只留在用户设备上。

## 不要做的事

- 不要编造本包没有的仓库、星数、日期或榜单名次。
- 不要把采样星数说成实时星数，也不要说自己刚从 GitHub 查过。
- 不要承诺平台会自动推送、自动联网更新，或自动执行 `reader/` 里的 HTML。
- 不要把本 Skill 包说成小工具容器合规认证。那是另一种 ZIP，根目录是 HTML 入口，不是 `SKILL.md`。本包里的展示页在 `reader/index.html`。
- 不要建议把私人项目笔记发布到公开页面。
