Plannotator


GitHub 上的开源项目。AI 写代码前会先出一份计划（plan），Plannotator 把这份计划在浏览器里打开，你像批改作文一样划线、写批注，点一下就把意见发回给 AI；AI 改完，还会标出计划前后的差别。代码写完，它也能打开审查页面，让你逐行点评本地改动或 GitHub 上的 PR。支持 Claude Code、Codex、Gemini CLI、Copilot CLI、OpenCode 等十来种 AI 编程工具。

它能做什么


    

  • 审计划：AI 准备动手时，计划自动在浏览器里弹出。你逐段批注，点「通过」AI 才往下做；点「打回」，批注会整理好发回去，AI 改完再给你看前后差别。
    • 

  • 审代码：/plannotator-review 打开本地还没提交的改动，或一个 GitHub / GitLab 的 PR，逐行写意见，意见直接回到 AI 的对话里。
    • 

  • 批注任何文档：/plannotator-annotate 能打开 Markdown 文件、整个文件夹、网址或 HTML 页面；/plannotator-last 批注 AI 刚才那条回复。
    • 

  • Inbox（收件箱）：几个 AI 同时干活时，把问题、文件、待审内容都投到一个本地窗口，你有空再统一回复，AI 不用干等。批准过的计划还能自动存进 Obsidian、Notion 或 Bear。

最突出的点


给 AI 的计划配一支红笔


AI 最贵的错，是一开始方向就错，写了几百行才发现。Plannotator 把「审计划」做得像改作文一样顺手：划一句，写一句意见，点发送。人只在两个关口出手：动手前看计划，合并前看改动。






适合谁用


已经在用 Claude Code、Codex 这类工具写代码，常遇到「AI 理解错需求、一口气改了一大片」的人。不会写代码也能用：看得懂计划、会写中文批注就行。










缺点与应对


    

  1. 缺点1：计划自动弹出，要靠各家 AI 工具的钩子（hooks）。Codex 用的是还在实验的 Stop 钩子，原生 Windows 要手动配置；Droid 目前只支持手动命令。
          应对：先用最稳的 /plannotator-last 和 /plannotator-review 两个手动命令，熟了再开自动审计划。装完先在一个练手仓库里试一次。
    2. 

  2. 缺点2：有几个功能会联网。页面打开时会向 GitHub 查新版本；批注网址默认经 Jina Reader 抓取；「问 AI」会把相关内容发给你配置的模型；分享链接时内容跟着链接走，小份内容只压缩、没加密。
          应对：私密代码别用分享链接，可以设置 PLANNOTATOR_SHARE=disabled 把分享关掉。远程模式会在所有网卡上开端口、不用登录，只在可信网络里用。
    3. 

  3. 缺点3：安装是「一行命令下载脚本直接运行」，还会改你 AI 工具的配置。
应对：先打开安装脚本看一眼，或加 --minimal 只装主程序；想撤销就运行 plannotator uninstall，默认保留你的计划和历史。

价值在于对付 AI 的「知识过期」：模型训练数据里老代码多，它就习惯写老办法。这个项目把指南压得很短（装进 AI 的入口说明约 205 个 token），用到时才查全文，不多占 AI 的上下文。


更值得学的是评测方法：每个任务先准备标准答案（打分器必须给 100% 通过）和没改过的原始网页（必须 100% 不通过），用来校准打分器；再比较 AI 装与不装指南的通过率。模型本来就会的内容删掉，只留真正能提分的。这套「先出考卷再写教材」的做法，任何写 skill 的人都能照搬。
